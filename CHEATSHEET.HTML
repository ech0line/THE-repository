GIT CHEATSHEET

Trygg arbeidsflyt · Git Bash · VS Code · GitHub

1. Førstegangsoppsett

Installer Git og VS Code. Kjør i Git Bash:

git config --global user.name "Ola Nordmann"
git config --global user.email "ola@example.com"
git config --global init.defaultBranch main
git config --global --list

2. Opprett repository

Opprett et repository på GitHub, kopier URL-en og klon:

cd /c/projects
git clone <url>
cd <prosjektnavn>
code .
Viktig: Ikke kjør git init etter git clone.

3. Daglig arbeidsflyt

PULL → JOBB → COMMIT → PUSH

git status
git pull
# Jobb i VS Code
git status
git diff
git add .
git commit -m "Beskriv endringen"
git push
git status
  • status – viser status og branch.
  • pull – henter endringer fra GitHub.
  • diff – viser endringene.
  • add . – klargjør endringer.
  • commit – lagrer et kontrollpunkt.
  • push – sender commits til GitHub.

Commit ofte med beskrivende meldinger. Sikt på working tree clean før du avslutter.

4. Sikkerhet og .gitignore

  • Pull før arbeid; push før du avslutter.
  • Opprett .gitignore tidlig.
  • Ikke push passord, API-nøkler eller .env.
  • Hvis en hemmelighet er pushet, bytt den.
  • Unngå git reset --hard og git push --force uten å forstå konsekvensene.
node_modules/
.env
*.log

package.json og package-lock.json skal normalt pushes.

5. Branches og merge

Bruk gjerne bare main i enkle individuelle prosjekter.

git branch
git switch main
git switch -c login
git add .
git commit -m "Lag innlogging"
git push -u origin login

Merge inn i main:

git switch main
git pull
git merge login
git push

Før branch-bytte: sjekk git status og håndter ucommittede endringer.

6. Merge conflicts

Oppstår når Git ikke automatisk kan kombinere motstridende endringer.

  1. Les konflikten i VS Code.
  2. Velg hvilke endringer som skal beholdes.
  3. Kontroller at koden er riktig.
  4. Fullfør:
git add .
git commit -m "Løs merge conflict"
git push

Ikke slett .git eller kjør tilfeldige kommandoer for å løse problemet.

7. Feilsøking

Når noe er galt, start med:

git status
git branch
git remote -v
git log --oneline
  • status – tilstanden til repositoryet.
  • branch – aktiv branch.
  • remote -v – tilkoblet GitHub-repository.
  • log --oneline – kort commit-historikk.

8. Kontroller før du avslutter

  • Riktig mappe i VS Code?
  • Riktig branch, normalt main?
  • Riktig repository? Sjekk git remote -v.
  • Er siste commit pushet til GitHub?
  • Viser GitHub riktig branch og filer?
